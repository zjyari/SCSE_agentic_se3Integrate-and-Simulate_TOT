# SCSE '26 — Agentic Software Engineering Project

Multi-agent pipeline that turns a human-language robot-navigation brief into
working, **tested** Python code, through a chain of agents backed by Qwen,
across four phases: Requirements Engineering, Plan and Develop, Testing, and
Integration and Simulation.

```
brief.txt
   │  (Analyst Agent)
   ▼
artifacts/requirements.json      ← WHAT the software must achieve
   │  (Planner Agent)
   ▼
artifacts/plan.json              ← HOW the software should behave
   │  (Developer Agent)
   ▼
artifacts/navigation_logic.py    ← working Python implementation
   │  (decide_next_move(state))
   ▼
test_*.py                        ← two-level testing strategy
   │  (Test Agent + Simulation + Reviewer)
   ▼
artifacts/simulation_report.json ← 64-state simulation results
   │  (IR-SIM Benchmark + Benchmark Reviewer)
   ▼
artifacts/irsim_benchmark_report.json  ← 4-world IR-SIM results
   │
   ▼
trace.log                        ← full pipeline event log (main.py)
```

## Run the full pipeline

### Phases 1–3 (entry points, run in order)
Each agent's output is the next agent's input — context isolation: each agent
only receives the previous agent's artifact, not the whole conversation.

```powershell
# Phase 1 — Requirements Engineering
python brief_to_req.py     # optional: human-readable requirements -> robot_requirements.txt
python run_analyst.py      # -> artifacts/requirements.json

# Phase 2 — Plan and Develop
python run_planner.py      # -> artifacts/plan.json
python run_developer.py    # -> artifacts/navigation_logic.py
```

### Phase 4 — Integration and Simulation (single orchestrator)
Run everything from one place; every event is recorded in `trace.log`:

```powershell
python main.py
```

`main.py` runs the agents one after another:
1. Load the brief
2. **Analyst Agent** -> `artifacts/requirements.json`
3. **Planner Agent** -> `artifacts/plan.json`
4. **Developer Agent** -> `artifacts/navigation_logic.py` + `generated/navigation_logic.py`
5. **Test Agent** -> `generated/test_decide_next_move.py`, executed with pytest
6. **Simulation** (runner) -> `artifacts/simulation_report.json` (all 64 states)
7. **Reviewer Agent** -> `artifacts/review_report.json`
8. **IR-SIM benchmark** -> `artifacts/irsim_benchmark_report.json` (4 worlds)
9. **Benchmark Reviewer** -> `artifacts/benchmark_review_report.json`
10. If any reviewer requires a revision: **Developer Agent revision** ->
    `generated/navigation_logic_revised.py`, then re-test and re-run the
    simulation + IR-SIM benchmark.

Interactive visual check of the IR-SIM worlds (opens a window per world):

```bash
bash run_visual.sh irsim_worlds/world_easy.yaml
bash run_visual.sh irsim_worlds/world_medium.yaml
bash run_visual.sh irsim_worlds/world_hard.yaml
bash run_visual.sh irsim_worlds/world_custom.yaml
```

> Automated benchmark runs are headless (`MPLBACKEND=Agg`), so no windows
> pop up during `main.py` / `benchmark_irsim.py`.

## Testing strategy (two levels)

### Level 1 — Agent / Pipeline smoke tests
Run the actual agents with their real inputs; each agent's own validation
accepts or rejects its output:

```powershell
python test_analyst.py     # brief.txt -> Analyst -> artifacts/requirements.json
python test_planner.py     # requirements.json -> Planner -> artifacts/plan.json
python test_developer.py   # plan.json -> Developer -> artifacts/navigation_logic.py
```

Each script stores its output in `artifacts/` and displays it after the test
ends. The Developer test also asserts that `decide_next_move(state)` exists.

### Level 2 — Behavioral testing
Call `decide_next_move(state)` with known states and check the returned action:

```powershell
python test_generated_navigation_logic.py
```

The test enumerates **all 2^6 = 64 possible states** (six boolean sensor
signals), checks that every returned action is a valid action
(FORWARD/LEFT/RIGHT/STOP) and the correct expected move. It includes the
tricky states: goal direction blocked, multiple goal signals, everything
blocked, and no goal signal at all.

The `state` dict (sensor input) is:
```python
{
  "goal_ahead": bool, "goal_on_left": bool, "goal_on_right": bool,
  "front_blocked": bool, "left_blocked": bool, "right_blocked": bool
}
```

Expected behaviour — decision order (used by the tests, the runner and the
revised navigation logic):
```
if goal_ahead      and not front_blocked: FORWARD
elif goal_on_left  and not left_blocked:  LEFT
elif goal_on_right and not right_blocked: RIGHT
elif not front_blocked:                   FORWARD   # obstacle avoidance
elif not left_blocked:                    LEFT      # obstacle avoidance
elif not right_blocked:                   RIGHT     # obstacle avoidance
else:                                     STOP
```
The robot prefers moving toward the goal when safe, never moves into a
blocked direction, and — to reach the goal in a real environment — manoeuvres
around obstacles (a blocked goal direction does **not** force a stop as long
as another direction is clear). It stops only when all directions are blocked.

### Bug-detection check (required by the assignment)
1. Introduce a bug into `artifacts/navigation_logic.py` (e.g. swap LEFT and
   RIGHT in one branch).
2. Run `test_generated_navigation_logic.py` again → at least one test fails.
3. Remove the bug and run all tests again → all pass.

This confirms the test cases actually catch bugs instead of merely printing
"passed". Results of this check are recorded in the run below.

## Agent contracts

### Analyst Agent (`analyst_agent.py`)
Output JSON (produced by Qwen, validated by `validate_requirements`):
```json
{
  "goal": "string",
  "allowed_actions": ["FORWARD", "LEFT", "RIGHT", "STOP"],
  "safe_stop": true,
  "avoid.obstacles": true
}
```
> The fourth key is literally `avoid.obstacles` (with a dot), exactly as
> written in the project-instructions PDF. No extra keys, no extra actions.

### Planner Agent (`planner_agent.py`)
Output JSON (produced by Qwen, validated by `validate_plan`):
```json
{
  "strategy": "overall navigation strategy",
  "decisions": ["decision 1", "decision 2"],
  "stop_condition": "when the robot must stop"
}
```

### Developer Agent (`developer_agent.py`)
Output: raw Python code (produced by Qwen, validated by `validate_code` using
`ast.parse` — must be syntactically valid and **define the main function
`decide_next_move(state)`**; helper functions are allowed, but other
agents/programs call only `decide_next_move(state)`). Saved as
`artifacts/navigation_logic.py`.

In Phase 4 the agent also exposes `run_developer_revision(original_code,
review_notes, benchmark_report, requirements, plan)` which generates a
**revised** navigation logic (saved as `generated/navigation_logic_revised.py`)
when a reviewer requires a revision.

### Test Agent (`test_agent.py`)
Generates pytest tests from the requirements and plan artifacts (saved as
`generated/test_decide_next_move.py`). `validate_test_code` checks the code is
non-empty, has no markdown fences, imports a module, defines `test_*`
functions with `assert`, and parses with `ast.parse`. The expected actions
follow the decision table in the prompt (goal-first, then obstacle
avoidance, STOP only when everything is blocked).

### Simulation runner (`runner.py`)
Enumerates all 2^6 = 64 states, compares `decide_next_move(state)` against
the expected decision table, and writes `artifacts/simulation_report.json`
(total/passed/failed/success_rate/results).

### Reviewer Agent (`reviewer_agent.py`)
Reviews the simulation report; output JSON: `issue`, `likely_cause`,
`recommendation`, `needs_revision` (bool). `needs_revision` is true when the
report shows any failed scenario.

### IR-SIM benchmark (`benchmark_irsim.py`)
Runs `test_irsim_with_agent.py` headless on each of the 4 world files
(easy/medium/hard/custom), extracts each world's report, and writes
`artifacts/irsim_benchmark_report.json` (total_worlds, goals_reached,
success_rate, efficient_worlds, inefficient_success_worlds, failed_worlds,
efficiency_rate, average_steps_taken, results).

### Benchmark Reviewer Agent (`reviewer_benchmark_agent.py`)
Deterministic review from measured fields: safety (any world where the robot
finished without reaching the goal), goal completion (success_rate < 1.0),
efficiency (inefficient successful worlds or efficiency_rate < 1.0). The LLM
only phrases the issue/cause/recommendation; the pass/fail booleans always
come from the measured numbers. Output JSON: `issue`, `likely_cause`,
`recommendation`, `safety_passed`, `goal_completion_passed`,
`efficiency_passed`, `needs_revision`.

## Validation

Every agent validates its own output before returning:
- `validate_requirements()` — dict shape, exact 4 keys, correct types, allowed actions only.
- `validate_plan()` — dict shape, exact 3 keys, non-empty strategy / decisions / stop_condition.
- `validate_code()` — parses as valid Python, defines `decide_next_move(state)`.
- `validate_test_code()` — parseable Python with a module import, `test_*` functions and `assert`.
- `validate_review()` / `validate_benchmark_review()` — exact JSON keys and types.

Each agent retries (with a correction instruction) up to 2 times if Qwen's
output does not validate.
